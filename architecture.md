# Architecture

This bot places an outbound call via Twilio, which streams the live call audio to a small FastAPI server over a WebSocket (Twilio Media Streams). That server bridges the audio directly to OpenAI's Realtime API — a speech-to-speech model that consumes and produces audio natively, with no separate transcription or text-to-speech step in between. Both sides are configured to use G.711 μ-law audio, Twilio's native telephony format, so no audio conversion happens anywhere in the pipeline — this was the main lever available for minimizing latency and keeping turn-taking natural. Call recording is handled natively by Twilio (`record=True`) rather than custom audio capture, and the transcript is captured live from the Realtime API's own transcript events as the call happens. Scenario personas and goals live in `config/scenarios.yaml`, fully separate from the bridge/orchestration code in `src/`, so retargeting this bot at a different business or adding new test scenarios only requires editing the config, not the code.

I chose the Realtime API over a cascaded STT → LLM → TTS pipeline because the top evaluation priority for this challenge was conversational naturalness and turn-taking, and a cascaded pipeline stacks latency across three independent network round-trips while requiring interruption handling to be built manually at each seam. The Realtime API avoids both problems by design. I also considered using a third-party conversational voice platform (e.g. Vapi, Bland, Retell) that owns the entire conversation loop, but ruled it out since the challenge specifically asks for a bot built in Python, and offloading the hardest part of the system to a platform would weaken both the "working code" and "architectural reasoning" evaluation criteria. The main known limitation of the current approach is that interruption handling clears Twilio's queued audio but doesn't track exact playback position for sample-accurate mid-word truncation, and prompt-based instructions to avoid overlapping the other party's opening greeting reduced but didn't fully eliminate occasional overlap — likely genuine model-level non-determinism rather than a fixable wording issue.
